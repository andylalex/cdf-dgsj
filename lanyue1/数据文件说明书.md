# 蓝月产品原型工作台 · 数据文件说明书

> **版本**：v3.0　**适用目录**：`中免项目/lanyue1/`
> **地位**：本文件是**唯一契约**。人工编辑、AI 修改、管理模式回写，三方都必须遵守。
> **铁律**：改任何数据文件前先读本文件；改格式必须同步更新本文件；工作台升级后必须同步更新本文件。

---

## 1. 总原则

| 原则 | 说明 |
|---|---|
| **单一权威源** | 每个数据只有**一个**文件负责写。禁止两个文件渲染同一个组件 |
| **结构与内容分离** | 结构（分组/顺序）在 HTML 内联；内容（需求/流程/标注）在 `data/prototypes.js` |
| **单向关联** | 结构通过 `id` 引用内容，**内容里禁止写 `group`/`order`** |
| **回写唯一通道** | 一切持久化必须经 `serve.py` 的 API，前端不得自行写文件 |

### 三层分工

| 层 | 权威文件 | 谁改 | 内容 |
|---|---|---|---|
| **结构层** | `index.html` / `admin.html` 内联 `<script id="wb-nav">` | 管理模式 → `serve.py` 同步写两个 HTML | 品牌、分类、条目顺序、图标、角标 |
| **内容层** | `data/prototypes.js` | 管理模式 → `serve.py` | 每个原型的全部业务内容 |
| **资产层** | `v0.4/*.html`、`assets/brand/*` | 只读（serve.py 拒绝写） | 原型页面与图片 |

## 3. 内容层：`data/prototypes.js`

```js
window.PROTO_DATA = { v: 3, generated: "2026-09-17", models: {...}, items: {...} };
```

### 3.1 `items` —— 原型实体字典（**无序**，键为 id）

```js
"v04-u1": {
  id:        "v04-u1",                  // 必填，与键同名
  name:      "U1 用户端 IM 会话页",      // 必填
  device:    "mobile"|"desktop"|"tablet",
  status:    "review"|"wip"|"done",
  version:   "v0.4",
  owner:     "产品 · 梁伟业",
  updated:   "2026-09-16",
  kind:      "page"|"pages"|"images",   // 单页 / 多页切换器 / 图片稿
  url:       "v0.4/U1-用户端IM会话页.html",  // kind=page 时必填
  thumb:     "assets/brand/xxx.png",   // 可选：目录页/切换用的预览图
  pages:     [{ name:"定制品牌馆", url:"v0.4/U10-品牌馆页.html" }],  // kind=pages
  images:    [{ name:"", url:"" }],     // kind=images
  overview:  { summary, path, users, permission, ports, goal, note },
  flow:      [{ t:"步骤名", d:"说明" }],
  states:    [{ n:"状态名", d:"说明" }],
  exceptions:[{ t:"异常名", d:"说明" }],
  rules:     [{ code, trigger, behavior, exception }],
  api:       [{ name, method, path, desc }],
  fields:    [{ name, type, required, format, sample }],
  acceptance:[ "可勾选的验收项" ],
  note:      "备注",
  hotspots:  [ /* 见 3.2 */ ]
}
```

**硬性约束**
1. **禁止**在 `items[*]` 里写 `group` / `order` / `icon` / `badge` —— 这些属于结构层。
2. 数组字段缺失一律按 `[]` 处理；字符串缺失按 `""` 处理。渲染必须优雅降级。
3. `id` 全局唯一，是结构与内容的**唯一联结键**。

### 3.2 `hotspots` —— 元素标注

```js
{
  id: "u4-e1",            // 必填，唯一
  selector: "#xxx",       // 原型页内 CSS 选择器（用于自动定位）
  type: "element"|"rule"|"field",
  x: 0.5, y: 0.2, w: 0.8, h: 0.1,   // 相对比例 0~1（无 selector 时按此定位）
  num: 1,                 // 显示编号，缺失则按数组顺序补
  title: "行程核验卡片",
  desc: "多行说明\n第二行",
  fixed: false,           // true = 固定在视口
  rule:  { code, trigger, behavior, exception },
  field: { type, required, format, sample }
}
```

### 3.3 `models` —— 数据模型（右栏「数据」页）

```js
"Product": { label:"商品", sources:["v04-g4","v04-u6"], fields:[{name,type,required,format,sample}] }
```
`sources` 是原型 id 数组；右栏按 `sources` 反查，展示「本页面涉及的数据模型」。

## 4. 结构层：内联 `<script id="wb-nav">`

两个 HTML 内各有一份**逐字节相同**的 JSON，`serve.py` 回写时同步更新两份。

```html
<script id="wb-nav" type="application/json">
{ "v":3,
  "brand": { "name":"蓝月", "sub":"LANYUE PROTOTYPE WORKBENCH" },
  "cats":  ["用户端 · CDF中免海南", "导购端 · 繁星APP", "管理后台 · PC"],
  "items": [ { "id":"v04-u1", "group":"用户端 · CDF中免海南", "order":0, "icon":"", "badge":"" } ] }
</script>
```

**约束**
1. `items` 的**数组顺序即渲染顺序**，同 `group` 的聚在一起。
2. `items[].id` 必须在 `data/prototypes.js` 的 `items` 里存在；不存在的条目渲染时跳过并计数为「悬空」。
3. `data/prototypes.js` 里有、但 `wb-nav.items` 里没有的实体 = **未挂载**，管理模式「添加页面」可挂载。
4. **导航数据不再存 js 文件** —— 这是为了根除 `nav-data.js` 的缓存问题（旧版痛点）。

## 5. 模块契约（`assets/js/`）

加载顺序固定：`core → cache → data → sidebar → stage → panel → app`（`editor` 仅 admin，在 app 之后）。

| 模块 | 全局 | 必须提供 |
|---|---|---|
| core | `WBCore` | `esc/toast/on/emit/$/$$/v(url)/build/store/env` |
| cache | `WBCache` | `init/check/forceReload/assetUrl/onUpdate/lazy{lazyScript,lazyImage,lazyRender}` |
| data | `WBData` | `load()/proto(id)/all()/models()/nav()/saveNav(nav)/saveProto(data)/scan()` |
| sidebar | `WBSidebar` | `mount(root)/render()/setManage(on)/currentId()` |
| stage | `WBStage` | `mount()/show(proto)/setDevice(d)/reload()/renderPageTabs()` |
| panel | `WBPanel` | `mount(root)/render(proto)/setTab(name)/on(cb)` |
| editor | `WBEditor` | `mount()/toggle(on)/openAdd()/openEdit(id)` |
| app | — | 启动、路由、事件串联 |

**通用要求**
- 纯原生 JS，无框架、无 CDN、无 gsap。
- 所有动态文本必须 `WBCore.esc()` 转义。
- 所有 `fetch` 必须 try/catch 静默降级（`file://` 下会失败，不能白屏）。
- 所有资源 URL 必须走 `WBCore.v()` 拼版本号，禁止裸路径。

### 5.1 事件契约

| 事件 | 触发时机 | 载荷 |
|---|---|---|
| `route:change` | 路由变化 | `{view:'catalog'\|'proto', id, page}` |
| `proto:select` | 选中原型（左导航点击 / 路由） | `proto` 对象 |
| `proto:changed` | **管理模式保存后** | `proto` 对象（右栏监听它刷新） |
| `nav:changed` | 导航结构变化 | `nav` 对象 |
| `data:reloaded` | 数据文件重新加载 | — |
| `hotspot:click` | 点击热点 | `{id, num}` |
| `data:stale` | 远端有新版本 | `{build}` |

**去重约定**：左导航点击会先 `emit('proto:select')`，随后 hash 路由再触发一次。因此 `app.js` 对同 id 做了 **400ms 内只发一次** 的节流，下游模块不得依赖"每次点击必触发两次"。

### 5.2 路由

`#/p/<protoId>/<pageIndex>` 为原型页；`#/catalog` 或空为目录页。子页序号写进 hash，**刷新不丢状态**。

## 7. 落盘协议：`serve.py`

启动：`python3 serve.py <端口>`（默认 8850，8848 常被旧实例占用）。

| 接口 | 方法 | 入参 | 作用 |
|---|---|---|---|
| `api/version` | GET | — | 返回 `version.json` 内容（探测本地服务是否在线） |
| `api/scan` | GET | — | 扫描 `v0.4/*.html` 与图片，返回可添加文件列表 |
| `api/save-nav` | POST | `{nav}` | **同步写回两个 HTML 的 `#wb-nav`**，并自增版本号 |
| `api/save-proto` | POST | `{data}` 或 `{items,models}` | 写回 `data/prototypes.js` |
| `api/upload` | POST | `{path, b64}` | 上传图片到 `assets/brand/`（仅允许该目录） |
| `api/health` | GET | — | 健康检查 |

**安全约束**
1. 白名单：只允许写 `index.html`、`admin.html`、`data/prototypes.js`、`assets/brand/*`。
2. 写 HTML 必须**同时**更新两份且内容逐字节一致，否则返回错误。
3. 拒绝写 `v0.4/**`（原型页只读）与任何 `..` 路径。
4. 写前自动 `.bak` 备份到 `.workbuddy/backups/`。
5. 所有静态响应带 `Cache-Control: no-store`。

## 8. 缓存治理协议

1. **构建号唯一真相** = `version.json` 的 `build`（格式 `YYYYMMDD.NN`）。
2. 静态资源 `?v=` 由 `bump.py` 统一替换（`WB_BUILD` 内联常量 + 所有 `?v=`）。
3. 运行时任何 URL 一律走 `WBCore.v(url)`，禁止字符串拼接裸路径。
4. 启动自检 `version.json`（`cache:'no-store'`），每 5 分钟轮询；页面隐藏时暂停，切回立即检查。
5. 发现新版本 → 顶部 `.wb-update-bar` 提示 + 一键刷新（**不自动刷新**，避免打断评审）。
6. `forceReload()` 四层兜底：清 CacheStorage → SW skipWaiting → `location.reload(true)` → `location.replace(path?_wb=ts+hash)`（保留 hash）。
7. iframe 切换必须先 `about:blank` 再赋新 src，并用 `data-src` 去重。
8. `file://` 下不注册 SW、关闭网络自检，全部静默。
9. **严禁**给 `sw.js` 加 HTML 预缓存（等于把旧版钉死在用户机器上）。
10. localStorage 命名空间 `lanyue_wb_v2_`；右栏验收勾选 `wbacc_<protoId>`、管理态 `lanyue_wb_manage`、主题 `lanyue_wb_theme`。
    **清理时白名单保护**：`lanyue_wb_v2_*`、`wbacc_*`、`lanyue_wb_manage`、`lanyue_wb_theme`、`lanyue_wb_edit_v1`（旧版遗留）。
11. **版本号必须两处同源**：`version.json` 的 `build` 与两个 HTML 内联的 `<meta name="wb-build">`、`?v=` 必须一致。
    任何写盘（管理模式保存）只要自增了 build，就必须同步回写 HTML 的版本号，**否则在线页面会把自己误判成旧版、反复弹更新横幅**。

## 9. 性能要求

| 项 | 要求 |
|---|---|
| 外链 | **零外网 CDN**（字体用系统栈，图标用内联 SVG） |
| 体积 | 已移除 gsap(72KB) 与 511KB logo（改用 3.5KB `mark.jpg`） |
| 懒加载 | 图片 `data-src` → IntersectionObserver；iframe `loading="lazy"`；JS 按需 `WBCache.lazy.lazyScript()` |
| 渲染 | 右栏非当前 tab 不建 DOM；左导航一次渲染不重复刷新 |
| 事件 | 一律事件委托，禁止逐行 addEventListener |

## 10. 自检清单（每次发布前）

```bash
python3 bump.py "本次改动说明"      # 1. 升版本号
node .workbuddy/lint.js            # 2. 静态合规：标签配平 / 无外链 / 引用完整 / 双文件 NAV 一致
node .workbuddy/verify.js          # 3. 渲染断言：左导航 / 舞台 / 右栏 / 路由
node .workbuddy/verify.js "http://127.0.0.1:8850/admin.html"   # 4. 管理模式页
node .workbuddy/test_manage.js "http://127.0.0.1:8850"         # 5. 管理模式端到端（真加页→回写→恢复，19 项）
```

> `test_manage.js` 会真写一次数据文件再恢复，跑之前确保 `serve.py` 在同一端口运行。

必查项：
- [ ] 两个 HTML 的 `#wb-nav` 逐字节一致
- [ ] `version.json` 的 build 与 HTML 内联 `WB_BUILD` 一致
- [ ] 无 `http://` / `https://` 外链资源
- [ ] `data/prototypes.js` 里没有 `group` / `order` 字段
- [ ] 悬空条目数 = 0（除明确未挂载的）
- [ ] 本说明书已随改动更新

## 11. 发布顺序（GitHub Pages 无自定义响应头，顺序不能反）

1. `python3 bump.py "说明"` → 生成新 build
2. **先推 `version.json`**（在线页面靠它轮询发现更新）
3. 再推其余文件
4. 同步到 WorkBuddy 资料库
5. 线上复核：`python3 产物/.workbuddy/verify_remote.py "路径:关键词"`

顺序反了会让用户拿到「新外壳 + 旧版本号」，状态错乱。
